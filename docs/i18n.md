# i18n: next-intl (English + Arabic)

Set up 2026-10-03 with next-intl 4.14 on Next 16.3. English is the default; Arabic is RTL. Both languages are built together in every change.

## Routing

- **Prefix: `always`** (next-intl's default). Every page lives at `/en/...` or `/ar/...`.
- **Visiting `/`** (or any unprefixed path) gives a 307 redirect to a locale. The locale is chosen in this order: the `NEXT_LOCALE` cookie, then the `Accept-Language` header, then `en`. Crawlers send no `Accept-Language`, so they land on `/en`.
- **hreflang:** declared in each page's HTML by `lib/seo` (`seo.md#languages`). The proxy's `Link` header is off (`alternateLinks: false`), because its `x-default` pointed at the unprefixed URL and disagreed with the HTML.
- **Static rendering:** the root layout is `app/[locale]/layout.tsx`, and it exports `generateStaticParams` for both locales. `src/i18n/request.ts` reads the locale with `next/root-params`, so **`setRequestLocale` isn't needed**. Pages under `[locale]` are statically generated unless they opt into dynamic rendering.
- **`src/proxy.ts`** runs next-intl's middleware on every path except `api`, `_next`, `_vercel` and files with an extension.

| File | Role |
| --- | --- |
| `src/i18n/routing.ts` | Locales, default locale, `localeDirection` (`ltr` / `rtl`) |
| `src/i18n/navigation.ts` | Locale-aware `Link`, `redirect`, `usePathname`, `useRouter`, `getPathname` |
| `src/i18n/request.ts` | Per-request locale + messages |
| `src/i18n/types.ts` | Typed locales and message keys, plus the en/ar key parity check |
| `src/proxy.ts` | Locale detection, redirects, hreflang `Link` headers |
| `messages/{en,ar}.json` | One bundle per language |

**Always import navigation from `@/i18n/navigation`**, never from `next/link` or `next/navigation`. The plain versions drop the locale prefix. `notFound` is the exception: it still comes from `next/navigation`.

## Messages

- Namespaces are named per page or component, in PascalCase (`Home`, `NotFound`, `Metadata`, and later `Nav`, `Contact`, …).
- **Edit `en.json` and `ar.json` in the same change.** `src/i18n/types.ts` makes `tsc` (and `next build`) fail when either file has a key the other lacks.
- Keys are typed from `en.json`, so `t('typo')` doesn't compile.
- **Inline markup** uses next-intl rich text: write `<code>Next.js</code>` in the message and render it with `t.rich('key', { code: (chunks) => … })`. Never split a sentence into several keys.
- **Arabic copy:** Modern Standard Arabic, written natively. Product and tech names stay in Latin script (`أعمل بـ Next.js`), as the design-system README says. Claude drafts the Arabic and Ram reviews it.
- Content managed from `/console` (projects, editable text) is stored per locale in the database, not in these bundles. These bundles hold UI copy only.

## RTL

- `<html lang dir>` is set from the URL locale in the root layout.
- **Layout:** use logical utilities only (`ps-*`, `pe-*`, `ms-*`, `me-*`, `start-*`, `end-*`, `text-start`, `border-s`). Never use `pl-*`, `pr-*`, `left-*` or `right-*` for anything that should mirror.
- **Icons:** directional icons (arrows, chevrons) mirror with `rtl:-scale-x-100`. Don't mirror code, numbers, media controls or the logo.
- **Type:** components write `text-display`, `text-h2` and `text-body` in both languages. Under `:lang(ar)`, `globals.css` swaps them to the Arabic metrics (`display-ar`, `h2-ar`, `body-ar`) and removes letter-spacing and uppercase. See `design-system.md#tokens`.

## Numbers and dates

- The locale code is the bare **`ar`**. In current CLDR (Node 22, modern browsers), `ar` formats **Western digits** (`4.9`, `13 نوفمبر 2021`), which the design system requires. Regional tags like `ar-EG` or `ar-SA` switch to Arabic-Indic digits (`٤٫٩`), so don't introduce them.
- Format through next-intl (`format.number`, `format.dateTime`, ICU `{n, number}`) or date-fns with the matching locale. Never build a number string by hand.

## Not-found behaviour

- `app/[locale]/[...rest]/page.tsx` calls `notFound()` for any unknown path under a locale, so `app/[locale]/not-found.tsx` renders the localized 404 page.
- **Next 16.3 behaviour (checked 2026-10-03 in a fresh, minimal app):** when a page calls `notFound()`, the server returns **status 404 with `noindex`** and an error shell (`<html id="__next_error__">`). The not-found UI then renders from the RSC payload in the browser. Only URLs that match no route at all get a server-rendered 404 page. This is how Next works, not a bug in our setup. Status and `noindex` are correct for SEO.
- Paths the proxy skips (anything with a file extension) fall through to Next's default 404 page.

## Console

- Decided 2026-10-04: the console is bilingual under the locale (`/en/console`, `/ar/console`), with full RTL and its strings in both bundles. The proxy and the root layout need nothing extra. Content edited there is stored per locale in MongoDB and entered through `LocalizedField` (`console.md#localized-field`).
